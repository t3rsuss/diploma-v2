# Установлення та запуск у Windows через Conda

## Призначення інструкції

Інструкція описує один спосіб установлення програми:
Miniconda або наявна Anaconda, окреме середовище Python 3.11
та запуск локального вебінтерфейсу.

Цільова платформа: Windows 10/11 x64.
Цей сценарій не призначений для Windows ARM64, Linux або macOS.

Потрібні інтернет і кілька гігабайтів вільного місця.
Якщо репозиторій приватний, автор повинен заздалегідь надати доступ.

Статус цієї редакції: підготовлено до перевірки на іншому комп'ютері.
Повний сценарій цієї редакції ще не підтверджений на чистій Windows.

Виконуйте блоки по черзі. Після помилки зупиніться.
Не виконуйте наступний крок, поки попередній не завершився успішно.

## 1. Установіть Miniconda

Якщо Miniconda або Anaconda вже встановлена, повторна інсталяція
не потрібна. Перейдіть до розділу 2.

Офіційна інструкція та посилання на інсталятор:
https://www.anaconda.com/docs/getting-started/miniconda/install

Виберіть інсталятор Miniconda для Windows x86_64.

Під час установлення:
1. Виберіть встановлення для поточного користувача (Just Me).
2. Залиште стандартне розташування, якщо воно прийнятне.
3. Не вмикайте додавання Miniconda до системного PATH.
4. Не потрібно робити Miniconda системним Python.
5. Завершіть установлення.

Версія Python в інсталяторі Miniconda може відрізнятися від 3.11.
Потрібний Python 3.11 буде встановлено в окреме середовище.

Не встановлюйте додатково Python Install Manager, VS Code,
Jupyter або повну Anaconda лише для запуску цієї програми.

## 2. Відкрийте потрібний термінал

У меню «Пуск» знайдіть Prompt, установлений разом із Miniconda
або Anaconda. Його назва може містити Anaconda Prompt
або Miniconda Prompt.

Виберіть звичайний Prompt на основі cmd.exe,
а не Anaconda PowerShell Prompt.

У цій інструкції команди призначені саме для цього Prompt.
Не змішуйте їх із командами PowerShell.

На початку рядка зазвичай буде (base).

Перевірте:

```bat
conda --version
```

Очікується номер версії Conda.

Якщо conda не знайдено, перевірте, що відкрито саме Prompt
із меню встановленої Miniconda або Anaconda.
Не змінюйте Execution Policy і не налаштовуйте PowerShell
для проходження цієї інструкції.

## 3. Створіть окреме середовище

Спочатку перевірте наявні середовища:

```bat
conda env list
```

Якщо diploma-demo вже існує, не видаляйте його навмання.
Для першої незалежної перевірки потрібне нове середовище.
Зверніться до автора або узгодьте іншу назву для всіх команд.

Створіть середовище:

```bat
conda create --name diploma-demo --override-channels --channel conda-forge python=3.11 pip git -y
```

Команда встановлює Python 3.11, pip і Git.
Зазначений канал застосовується до цієї команди;
глобальна конфігурація каналів не змінюється.

Дочекайтеся завершення. Потім активуйте середовище:

```bat
conda activate diploma-demo
```

Перевірте:

```bat
python --version
python -c "import sys, struct; print('Executable:', sys.executable); print('Bits:', struct.calcsize('P') * 8)"
python -m pip --version
git --version
```

Очікується:
- Python 3.11.x;
- Bits: 64;
- шлях до Python усередині середовища diploma-demo;
- успішний вивід версій pip і Git.

Не встановлюйте залежності проєкту в base.

## 4. Завантажте програму

У Провіднику створіть нову порожню папку для перевірки,
наприклад DiplomaGuideCheck в «Документах».

Скопіюйте її повний шлях із рядка адреси Провідника.
У Prompt перейдіть у цю папку.

Приклад: замість C:\YOUR_FOLDER вставте фактичний шлях.
Лапки залиште.

```bat
cd /d "C:\YOUR_FOLDER"
```

Завантажте репозиторій:

```bat
git clone [https://github.com/t3rsuss/diploma-v2.git](https://github.com/t3rsuss/diploma-v2.git)
```

Після успішного завершення:

```bat
cd diploma-v2
```

Перевірте:

```bat
git rev-parse --short HEAD
dir requirements.txt
dir app.py
```

Запишіть ідентифікатор коміту: це версія коду, яку ви перевіряєте.

Якщо GitHub повідомляє про відсутність доступу, автор повинен
надати його до репозиторію. Не передавайте токени чи паролі в чаті.

Якщо папка diploma-v2 уже існує, виберіть іншу порожню
батьківську папку. Не видаляйте попередню робочу копію.

## 5. Установіть залежності

Переконайтеся, що:
- на початку рядка є (diploma-demo);
- поточна папка містить requirements.txt і app.py.

Виконайте:

```bat
python -m pip install -r requirements.txt
```

Дочекайтеся завершення. Після успішного встановлення:

```bat
python -m pip check
```

Очікується:

```text
No broken requirements found.
```

Зафіксуйте фактично встановлені версії у локальний файл:

```bat
python -m pip freeze > installed-packages-check.txt
```

Цей файл потрібен для діагностики перевірки.
Не потрібно додавати його в репозиторій.

Повідомлення Collecting, Downloading і Building wheel
самі по собі не означають помилку.

Якщо встановлення завершується з ERROR, не продовжуйте.
Збережіть повний вивід, включно з назвою пакета й причиною.

Не прибирайте фіксовані версії з requirements.txt
і не встановлюйте довільні інші версії для обходу помилки.

## 6. Завантажте готові моделі

Із кореня проєкту:

```bat
python tools\prepare_pretrained_models.py --download
```

Дочекайтеся завершення завантаження та перевірки.

Очікуваний підсумок:

```text
Verified required models: 5
```

Мережеве завантаження може тривати довго.
Після попередження перевіряйте кінцевий результат:
саме попередження ще не означає невдалого встановлення.

Якщо перевірка розміру або SHA-256 не пройшла,
не продовжуйте з неперевіреними моделями.

Не копіюйте моделі з комп'ютера автора під час незалежної перевірки:
мета цього кроку — перевірити саме передбачене завантаження.

## 7. Підготуйте демонстраційні файли

Для перевірки відновлення структури:

```bat
python demo\prepare_demo.py
```

Очікується створення демонстраційних даних у data\demo_ready.

Якщо скрипт повідомляє, що папка вже існує,
не видаляйте її автоматично. Для першої перевірки
використовуйте нову копію репозиторію.

## 8. Запустіть автоматизовані тести

```bat
python -m pytest tests -q
```

Дочекайтеся кінцевого підсумку й запишіть його.
Наявність FAILED або ERROR потрібно дослідити до підтвердження
працездатності встановлення.

Кількість тестів залежить від перевірюваного коміту.
Порівнюйте результати лише для відповідної версії коду.

## 9. Запустіть вебінтерфейс

```bat
python -m streamlit run app.py --server.address 127.0.0.1 --server.port 8503
```

Відкрийте у браузері:

http://127.0.0.1:8503

Залиште термінал відкритим.
Зупинення сервера: Ctrl+C у цьому терміналі.

Програма працює локально на вашому комп'ютері.
Браузер використовується як інтерфейс.

## 10. Перевірте аналіз одного файла

1. Відкрийте «Аналіз файла».
2. Завантажте безпечний тестовий файл відомого формату.
3. Натисніть «Проаналізувати».
4. Перевірте появу результату.
5. Спробуйте зберегти JSON-звіт.

Для перевірки можна використати власний PNG-файл.
Не використовуйте реальні шкідливі зразки на звичайному комп'ютері.

Окремо перевірте довільний тестовий файл без відомого формату.
Повідомлення про невстановлений формат не дорівнює помилці:
для невідомих даних система може сформувати лише припущення.

Успішний запуск сторінки сам по собі не підтверджує
коректну роботу всіх гілок аналізу.

## 11. Перевірте відновлення структури

1. Відкрийте «Відновлення структури».
2. Виберіть «XDT3 — демонстраційний читач».
3. Завантажте 20 файлів із data\demo_ready\xdt3.
4. Натисніть «Відновити та проаналізувати».
5. Перевірте появу підсумку й гіпотез полів.
6. Спробуйте зберегти JSON-звіт.

XDT3 є синтетичним демонстраційним форматом.
Читач обирається користувачем.
Це не автоматичне визначення назви довільного невідомого формату.

## 12. Повторний запуск

Після закриття програми або перезавантаження комп'ютера
знову відкрийте той самий Anaconda / Miniconda Prompt.

Активуйте середовище:

```bat
conda activate diploma-demo
```

Перейдіть у фактичну папку репозиторію:

```bat
cd /d "C:\YOUR_FOLDER\diploma-v2"
```

Запустіть:

```bat
python -m streamlit run app.py --server.address 127.0.0.1 --server.port 8503
```

Не потрібно повторно створювати середовище,
встановлювати залежності або завантажувати моделі,
якщо відповідні файли збережені.

## 13. Типові проблеми

### conda не знайдено

Відкрийте Prompt із меню встановленої Miniconda / Anaconda,
а не звичайний PowerShell.
Якщо такого Prompt немає, перевірте завершення встановлення.

### Середовище diploma-demo вже існує

Не видаляйте його без перевірки.
Для незалежного тесту узгодьте іншу назву
та використовуйте її в усіх командах.

### Python має неправильну версію або шлях

Повторіть conda activate diploma-demo,
потім перевірте python --version і шлях до інтерпретатора.
Не встановлюйте пакети в base.

### git не знайдено

Перевірте активацію diploma-demo.
Git установлюється в розділі 3 разом із Python.
Якщо створення середовища завершилося помилкою,
спочатку потрібно усунути саме її.

### requirements.txt або app.py не знайдено

Перейдіть у папку diploma-v2.
Команди встановлення й запуску виконуються з кореня репозиторію.

### pip не знаходить потрібну версію пакета

Перевірте Python 3.11 x64 і повний текст помилки.
Збережіть вивід для автора.
Не підміняйте версії залежностей без перевірки.

### Збій мережі або сертифікатів

Перевірте інтернет і правила корпоративної мережі.
Не вимикайте антивірус, брандмауер або перевірку TLS.
Збережіть адресу ресурсу й повний текст помилки без секретів.

### Перевірка моделей не пройшла

Не запускайте аналіз із неперевіреними файлами.
Збережіть діагностику.
Не видаляйте й не замінюйте робочі моделі навмання.

### Порт 8503 зайнятий

Зупиніть попередній сервер або запустіть на іншому порту:

```bat
python -m streamlit run app.py --server.address 127.0.0.1 --server.port 8504
```

Відкрийте http://127.0.0.1:8504.

### Браузер не відкрився

Введіть локальну адресу вручну.
Якщо в терміналі є traceback, спочатку потрібно усунути
помилку сервера, а не перевстановлювати браузер.

## 14. Що зафіксувати після перевірки

Передайте автору:
- версію й архітектуру Windows;
- версію Conda;
- версію та шлях Python;
- ідентифікатор коміту;
- підсумок pip check;
- підсумок перевірки моделей;
- підсумок pytest;
- результат обох перевірок у браузері;
- результат повторного запуску;
- installed-packages-check.txt;
- повний текст помилок, якщо вони були.

Не включайте паролі, токени або приватні досліджувані файли.

Перевірка вважається завершеною не після відкриття сторінки,
а після встановлення, тестів, перевірки обох режимів
і повторного запуску без додаткових команд поза інструкцією.

## 15. Межі застосування

Програма формує результати аналізу й гіпотези структури,
а не гарантує відновлення довільного формату.

Оцінка ризику не гарантує шкідливості чи безпечності файла.
Застосунок не є ізольованим середовищем для небезпечних зразків.

Історичні результати перевірок дивіться у FINAL_CHECK.md.
Вони не замінюють перевірку цієї редакції інструкції
на іншому комп'ютері.
