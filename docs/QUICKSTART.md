# Встановлення та запуск у Windows без Anaconda

## Для кого ця інструкція

Для користувача Windows 10/11 x64, який хоче завантажити програму
й запустити її локально в браузері. Anaconda та Conda не потрібні.

Потрібні:
- 64-бітний Python 3.11;
- Git;
- інтернет для першого встановлення;
- кілька гігабайтів вільного місця для пакетів, моделей та кешу;
- доступ до репозиторію, якщо він приватний.

Пакети встановлюються в окрему папку .venv усередині проєкту.
Системний Python не потрібно замінювати.

Команди вводяться у PowerShell без позначок PS>, >>> або префіксів
із прикладів термінала. Виконуйте блоки по черзі.
Після помилки зупиніться: наступний крок може залежати від попереднього.

## 1. Установлення Python 3.11

Якщо команда нижче вже працює і показує Python 3.11.x,
перейдіть до перевірки розрядності:

```powershell
py -3.11 --version
```

Якщо Python 3.11 ще немає:

1. Відкрийте офіційну сторінку Python Install Manager:
   https://www.python.org/downloads/latest/pymanager/
2. Завантажте запропонований інсталятор менеджера для Windows.
3. Відкрийте його та завершіть установлення.
4. Закрийте старі вікна PowerShell і відкрийте нове.
5. Установіть Python 3.11:

```powershell
pymanager install 3.11
```

Перевірте версію, шлях і розрядність:

```powershell
py -3.11 --version
py -3.11 -c "import sys, struct; print(sys.executable); print('bits:', struct.calcsize('P') * 8)"
```

Потрібні Python 3.11.x і bits: 64.

Якщо pymanager або py не знайдено, дивіться розділ помилок.
Не продовжуйте з довільною іншою версією Python.

## 2. Установлення Git

Якщо команда git --version працює, повторне встановлення не потрібне.

Інакше:

1. Відкрийте офіційну сторінку:
   https://git-scm.com/install/windows
2. Завантажте Git for Windows x64.
3. Установіть зі стандартними параметрами, які роблять Git доступним
   із командного рядка та сторонніх програм.
4. Відкрийте нове вікно PowerShell.

Перевірте:

```powershell
git --version
```

Git потрібен і для залежності thrember, яка встановлюється
з Git-репозиторію. Завантаження нашого проєкту ZIP-архівом
не усуває цю вимогу.

## 3. Завантаження проєкту

У Провіднику створіть порожню папку, наприклад DiplomaDemo
в «Документах». Відкрийте її, у рядку адреси Провідника введіть
powershell і натисніть Enter.

У відкритому вікні виконайте:

```powershell
git clone https://github.com/t3rsuss/diploma-v2.git
cd diploma-v2
```

Якщо папка diploma-v2 уже існує, не видаляйте її навмання.
Для незалежної перевірки виберіть іншу порожню батьківську папку.

Якщо GitHub відмовляє в доступі, автор має надати доступ
до приватного репозиторію. Паролі й токени не надсилайте
в повідомленнях або скриншотах.

Перевірте, що відкрито корінь проєкту:

```powershell
Get-Location
Test-Path requirements.txt
Test-Path app.py
```

Дві останні команди мають показати True.

## 4. Створення окремого середовища

Використовуйте саме py -3.11, а не випадковий python із PATH:

```powershell
py -3.11 -m venv .venv
```

Перевірте:

```powershell
.\.venv\Scripts\python.exe --version
```

Очікується Python 3.11.x.

Надалі використовується явний шлях до цього Python.
Активація середовища, Anaconda та зміна Execution Policy не потрібні.

Якщо .venv вже існує від іншого встановлення, не перезаписуйте її.
Почніть із нової копії проєкту або спочатку з'ясуйте її походження.

## 5. Установлення залежностей

Виконуйте кожну команду після успішного завершення попередньої:

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

Остання команда має повідомити:

```text
No broken requirements found.
```

Повідомлення Collecting, Downloading і Building wheel самі по собі
не означають помилку. Якщо встановлення завершується з ERROR,
подальші кроки не виконуйте.

Не змінюйте фіксовані версії пакетів для обходу помилки встановлення.

## 6. Завантаження готових моделей

```powershell
.\.venv\Scripts\python.exe tools\prepare_pretrained_models.py --download
```

Завантажувач отримує upstream-набір із 14 моделей.
П'ять потрібних нашому сценарію перевіряються за розмірами й SHA-256.
Також завантажується модель family близько 459 МБ,
яка цьому сценарію не потрібна. Це не завантаження датасету.

Залежно від мережі процес може тривати кілька хвилин або довше.
Успішне завершення позначається:

```text
Verified required models: 5
```

Попередження про відсутність HF_TOKEN не означає автоматичну відмову:
контрольний прогін завершився без токена. Обмеження сервісу можуть
змінюватися; орієнтуйтеся на фактичний результат завантаження.

Скрипт відмовляється автоматично замінювати наявні моделі
з неправильними контрольними сумами. Не ігноруйте цю відмову.

Власні моделі та готові Kaitai-парсери надходять із репозиторію.
Не відкривайте й не перезберігайте моделі текстовим редактором.

## 7. Запуск вебінтерфейсу

Із кореня проєкту:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py --server.port 8503
```

Відкрийте http://localhost:8503 у браузері.
Термінал має залишатися відкритим.

Угорі доступні:
- «Аналіз файла»;
- «Відновлення структури».

Зупинення сервера: Ctrl+C у терміналі.

Це локальний застосунок: браузер є інтерфейсом до програми,
яка працює на вашому комп'ютері.

## 8. Повторний запуск

Після перезавантаження комп'ютера відкрийте PowerShell
у папці diploma-v2 і повторіть лише:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py --server.port 8503
```

Повторно встановлювати залежності чи завантажувати моделі не потрібно,
якщо файли середовища та моделей збережені.

## 9. Аналіз одного файла

1. Виберіть «Аналіз файла».
2. Завантажте файл до 20 000 000 байтів.
3. Натисніть «Проаналізувати».
4. Перегляньте результат і за потреби збережіть JSON-звіт.

За вмістом система обирає доступну гілку:
спеціалізований аналіз PE/ELF, готовий опис стандартного формату
або попередній аналіз невідомих даних.

«Формат не встановлено» не означає збій програми.
Назву формату не визначено; карта областей та структурні кандидати
залишаються припущеннями.

## 10. Демонстрація відновлення структури

Один раз підготуйте окремі демонстраційні дані:

```powershell
.\.venv\Scripts\python.exe demo\prepare_demo.py
```

Команда створює data/demo_ready з 20 файлами XDT3 і 40 файлами CFG1.
Наявна папка не перезаписується. Якщо зразки вже підготовлені,
повторна генерація не потрібна.

На сторінці «Відновлення структури»:
1. Виберіть «XDT3 — демонстраційний читач».
2. Завантажте 20 файлів із data/demo_ready/xdt3.
3. Натисніть «Відновити та проаналізувати».
4. Перегляньте підсумок, гіпотези полів і пояснення довжин.
5. За потреби збережіть повний JSON-звіт.

Загальні обмеження сторінки:
5–30 різних файлів одного формату, кожен від 16 до 300 000 байтів.
Потрібен сумісний читач із доступного списку.

XDT3 і CFG1 — синтетичні демонстраційні формати.
Назву читача обирає користувач; алгоритм не визначає її автоматично.

## 12. Типові проблеми

### py або pymanager не знайдено

Перевірте встановлення Python Install Manager.
Закрийте старе вікно PowerShell і відкрийте нове.
Якщо проблема лишилася, збережіть вивід:

```powershell
Get-Command py, pymanager -ErrorAction SilentlyContinue
```

Не встановлюйте Anaconda лише для обходу цієї проблеми.

### Python 3.11 не знайдено

Виконайте встановлення через pymanager install 3.11,
потім повторіть py -3.11 --version.
Якщо менеджер не може отримати цю версію, не продовжуйте
з іншою версією без перевірки сумісності.

### git не знайдено

Установіть Git for Windows із доступністю в командному рядку
та відкрийте новий PowerShell.

### requirements.txt або app.py не знайдено

Ви не в корені проєкту. Перейдіть у завантажену папку diploma-v2.
Не запускайте встановлення з C:\Users\ім'я без переходу в проєкт.

### pip не знаходить потрібну версію пакета

Перевірте Python 3.11 x64, інтернет і налаштування джерела пакетів.
У корпоративній мережі можуть бути обмеження або власне дзеркало.
Не вимикайте перевірку TLS і не прибирайте фіксовані версії навмання.

### Помилка мережі, сертифіката або завантаження моделей

Збережіть повний текст помилки. Перевірте доступ до GitHub,
джерела Python-пакетів і Hugging Face відповідно до політики мережі.
Не вимикайте антивірус, брандмауер або перевірку сертифікатів.

### Model verification failed

Розмір або SHA-256 моделі не відповідає маніфесту.
Не продовжуйте аналіз із неперевіреним файлом.
Не перезаписуйте робочі оригінали без резервної копії.

### Port 8503 is already in use

Зупиніть попередній сервер через Ctrl+C або виберіть інший порт:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py --server.port 8504
```

Тоді відкрийте http://localhost:8504.

### Браузер не відкрився автоматично

Залиште термінал із сервером відкритим і введіть адресу вручну.
Якщо в терміналі є traceback, спочатку потрібно усунути помилку сервера.

### PowerShell блокує Activate.ps1

Ця інструкція не потребує Activate.ps1.
Використовуйте .\.venv\Scripts\python.exe, як у наведених командах.

## 13. Межі реалізації та перевірок

Програма формує гіпотези, а не гарантує відновлення довільного формату.
Незалежний парсер не генерується; сторонні EXE-читачі
автоматично не інструментуються.

Рівні ризику не гарантують шкідливості або безпечності.
Застосунок не є ізольованим середовищем для небезпечних зразків.

Підтверджено окреме встановлення повних залежностей на Windows
із Python 3.11.16, тести та окреме мережеве отримання моделей.
Наскрізний сценарій цієї редакції інструкції зі звичайним
Python поза Conda ще потребує перевірки.
Інші версії Python, ARM64, Linux і macOS цим гайдом не підтверджені.

Історія перевірок: FINAL_CHECK.md.
