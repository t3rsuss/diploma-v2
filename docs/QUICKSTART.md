# Встановлення та запуск у Windows

## 1. Підготовка

Потрібні 64-бітний Python 3.11, Git та інтернет.
Перевірена конфігурація: Windows, Python 3.11.16.
Під час встановлення Python увімкніть додавання Python до PATH.

Відкрийте PowerShell у папці, куди хочете завантажити проєкт.
Команди виконуйте послідовно; після помилки не переходьте далі.

## 2. Отримання програми

```powershell
git clone https://github.com/t3rsuss/diploma-v2.git
cd diploma-v2
```

Для отримання репозиторію потрібен доступ до нього в GitHub.
Якщо папка diploma-v2 вже існує, не перезаписуйте її цією командою.

## 3. Окреме середовище та залежності

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

Перед створенням середовища перевірте, що команда показує Python 3.11.
Активація середовища не потрібна: команди явно використовують його Python.

## 4. Готові моделі

```powershell
.\.venv\Scripts\python.exe tools\prepare_pretrained_models.py --download
```

Завантажувач отримує весь набір із 14 моделей, хоча нашому сценарію
потрібні п'ять. Зокрема завантажується модель family близько 459 МБ.
Завантаження може тривати кілька хвилин або довше залежно від мережі.

Ознака успішного завершення:

```text
Verified required models: 5
```

Потрібні моделі перевіряються за розміром і SHA-256.
Якщо наявні файли не відповідають маніфесту, скрипт не замінює їх
автоматично. Не обходьте помилку перевірки.

Власні моделі й готові Kaitai-парсери надходять із Git.
Не відкривайте й не перезберігайте файли моделей у текстовому редакторі.

## 5. Запуск

Із кореня проєкту:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py --server.port 8503
```

Відкрийте в браузері http://localhost:8503.
Термінал має залишатися відкритим. Зупинення — Ctrl+C.

Після наступного відкриття PowerShell достатньо перейти в папку
diploma-v2 і повторити команду запуску. Повторне встановлення не потрібне.

## 6. Аналіз одного файла

Виберіть «Аналіз файла», завантажте файл до 20 000 000 байтів
і натисніть «Проаналізувати».

Система визначає доступний тип за вмістом і обирає аналіз:
PE/ELF, готовий опис стандартного формату або попередній аналіз
невідомих даних. Звіт можна зберегти кнопкою експорту JSON.

«Формат не встановлено» не означає збій: відомої назви не визначено.
Гіпотези про ділянки не є підтвердженою специфікацією.

## 7. Відновлення структури за читачем

Це окремий режим для 5–30 різних файлів одного формату.
Кожен файл має бути розміром від 16 до 300 000 байтів.

Для демонстрації один раз підготуйте зразки:

```powershell
.\.venv\Scripts\python.exe demo\prepare_demo.py
```

Команда створює data/demo_ready і відмовляється перезаписувати
наявну папку. Якщо зразки вже підготовлені, цей крок пропустіть.

На сторінці «Відновлення структури»:
1. Виберіть «XDT3 — демонстраційний читач».
2. Завантажте 20 файлів із data/demo_ready/xdt3.
3. Натисніть «Відновити та проаналізувати».
4. Перегляньте підсумок, гіпотези полів і пояснення довжин.
5. За потреби збережіть повний JSON-звіт.

Для іншого набору потрібен сумісний читач із доступного списку.
Назву читача обирає користувач; алгоритм не визначає її автоматично.

## 8. Межі застосування

Результат відновлення — гіпотези структури. Незалежний парсер
не генерується, довільні сторонні EXE-програми не інструментуються.
Рівні ризику не є гарантією шкідливості або безпечності.
Застосунок не є ізольованим середовищем для небезпечних зразків.
