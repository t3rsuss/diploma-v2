# Обмеження та перевірка архівних читачів

Дата перевірки: 24.10.2026.
Коміт реалізації: 9e7ac7b.
Версія для порівняння до змін: df3726d.

## Область застосування

Обмеження реалізовані в experiments/e18_context.py, у run_ctx,
для вбудованих гілок gz та docx.

Гілка docx використовує zipfile для читання елементів ZIP.
Це не повна перевірка специфікації DOCX.

Ці обмеження не поширюються автоматично на довільний --reader
або інші засоби розпакування в проєкті.

## Налаштування

- MAX_EXPANDED_BYTES: 16 777 216 байтів, тобто 16 МіБ на архів.
- MAX_ZIP_MEMBERS: 1000 елементів ZIP, включно із записами каталогів.
- ARCHIVE_READ_CHUNK: до 65 536 байтів за один запит читання
  розпакованого потоку.

Для GZIP перевіряється сумарний обсяг повернутих розпакованих
даних, зокрема для послідовно з'єднаних GZIP-потоків.

Для ZIP попередньо перевіряються кількість елементів і сума
заявлених розмірів. Під час читання додатково контролюється
фактичний обсяг повернутих розпакованих даних.

Для виявлення перевищення допускається читання одного байта
понад залишок бюджету. Перевищення спричиняє ValueError.

## Сирі події та нормалізована траса

CtxIO.raw_log зберігає фактичні перехоплені події читання.
Обмеження кількості подій перевіряється за raw_log.

CtxIO.log використовується як робоча траса.
Для вмісту окремого ZIP-елемента суміжні читання об'єднуються,
лише якщо збігається контекст і наступне читання починається
безпосередньо після попереднього.

Нормалізація виконується окремо для кожного елемента.
Читання заголовка під час z.open не входять у цю ділянку
нормалізації. Різні контексти, розриви та різні елементи
не об'єднуються.

Це запобігає появі меж полів лише через поділ читання
вмісту ZIP-елемента на порції.

run_ctx повертає робочу трасу log. Сирий raw_log залишається
в об'єкті CtxIO під час виконання; його окреме експортування
у JSON-звіти зараз не реалізоване.

Порівнювалися результати одного алгоритму infer2 на однакових

відновлення за еталонною схемою.

## Межі захисту

Ліміт розпакованого обсягу не є загальним лімітом оперативної
пам'яті процесу. Внутрішні буфери бібліотек ним не обмежуються.

Кількість елементів ZIP перевіряється після відкриття архіву
та розбору його каталогу.

Не реалізовано ізоляцію читача в окремому процесі, жорсткий
тайм-аут або загальний ліміт CPU і пам'яті.
Реалізація не гарантує безпечної обробки довільних
недовірених архівів.
