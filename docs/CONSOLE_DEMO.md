# Відновлення невідомої структури за програмою-читачем

## Мета

За кількома зразками бінарних даних і доступною програмою-читачем
побудувати гіпотези про межі та ролі полів, використовуючи спостереження
за операціями читання.

Алгоритму відновлення не передається готова схема формату.
Програма-читач знає, як обробляти дані; система використовує журнал
її читань як джерело інформації про структуру.

## Поточна реалізація

Система працює з Python-читачами, які приймають файловий об'єкт.
Перехоплюються операції читання: позиція, кількість байтів і контекст
виклику. За кількома файлами алгоритм формує гіпотези про константи,
змінні поля, довжини, лічильники, типи записів, CRC-32 та блоки даних.

Це не автоматична інструментація довільної сторонньої EXE-програми.
Система не генерує незалежний парсер відновленого формату.

## Призначення прикладів

- XDT1, XDT2, XDT3: синтетичні формати для оцінювання відновлення.
- CFG1: демонстрація аналізу вмісту відновлених блоків.
- PNG, GIF, ICO, WAV, GZIP, DOCX: реальні формати для дослідження
  можливостей і обмежень трасування наявних читачів.

Правильна розмітка синтетичних форматів використовується оцінювачами,
а не передається як вхід алгоритму infer2.

## Консольна демонстрація

Команди виконуються з кореня diploma-v2 у середовищі diploma2.

### 1. Пояснення відновлення структури XDT3

Перед першим запуском підготуйте окремі демонстраційні дані:

    python demo/prepare_demo.py

Команда створює 20 XDT3 і 40 CFG1 у data/demo_ready.
Якщо ця папка вже існує, скрипт відмовляється її перезаписувати.
Повторно запускати підготовку для вже створеного набору не потрібно.

    python demo/explain_structure.py --samples data/demo_ready/xdt3 --reader demo.xdt3:parse_file --limit 20 --out results/explanation_ready_xdt3.json

Результат:

    results/explanation_ready_xdt3.json

Приклад пояснення: значення поля дорівнює 300, а пов'язане наступне
читання охоплює 300 байтів. Показано кількість числових збігів у вибірці
та наявність або відсутність збігу для конкретного файла.

Підтримка правила не є ймовірністю його семантичної правильності.
Для частини кандидатів збіг у конкретному файлі відсутній.

### 2. Спільний звіт про структуру XDT3

    python analyze_all.py --samples data/demo_ready/xdt3 --reader demo.xdt3:parse_file --limit 20 --out results/demo_ready_xdt3.json

Звіт містить межі й ролі полів, контекст читання, hex-перегляд,
аудит інтервалів, індикатори в блоках і журнал обробки зразків.

### 3. Пояснення правил для іншого читача

    python demo/explain_structure.py --samples data/demo_ready/cfg1 --reader demo.cfg1:parse_file --limit 40 --out results/explanation_ready_cfg1.json

Пояснювач приймає шлях до зразків і читач через аргументи.
Він пояснює правила довжин для першого файла вибірки.
Статистика підтримки правила підраховується за подіями всієї вибірки,
а не лише за цим файлом.

### 4. Кількісна перевірка на CFG1

Потрібні наявні зразки в demo/samples_cfg1.

    python experiments/e26_cfg1_structure_eval.py

Оцінюються точні межі, інтервали та пари «інтервал + роль».
Базовий варіант використовує межі читань без визначення ролей.
Суміжні константи перед порівнянням об'єднуються.

Результат на 40 зразках CFG1: infer2 отримав F1 = 1,000 за трьома
показниками; базовий варіант — F1 меж 0,939 та інтервалів 0,885.
Це результат спільного відновлення на синтетичному наборі,
а не незалежна оцінка універсальної точності.

## Відомі обмеження

- Усі придатні зразки поточного запуску беруть участь у відновленні.
- Гранулярність і спосіб читання впливають на результат.
- Траса не показує всі внутрішні операції нативних декодерів.
- Числові збіги можуть породжувати хибні гіпотези.
- Ширина поля може бути неоднозначною на обмеженій вибірці.
- Повне покриття файла інтервалами не означає правильності полів.
- У XDT3 відома хибна гіпотеза довжини для інтервалу [15, 17).
- Рівні ризику є евристичними індикаторами, не вердиктами
  про шкідливість і не ймовірностями.

## Статус дослідження

Історичні результати порівняння v1/v2, першого прогону XDT3,
подальших виправлень і порівняння з Kaitai зберігаються окремо.
Їх не слід перезаписувати запуском нової версії алгоритму.

Результати різних експериментів мають різні метрики й умови.
Перший прогін та результати після доопрацювання не є взаємозамінними.

Вебінтерфейс перевіряється на завершальному етапі.
