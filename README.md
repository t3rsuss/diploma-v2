# Інтелектуальна система реверс-інжинірингу структур бінарних даних

Кваліфікаційна (магістерська) робота, спеціальність 122 «Комп'ютерні науки», ІСЗЗІ КПІ ім. Ігоря Сікорського.

Система відновлює структуру невідомого бінарного формату за зразками файлів і програмою, що їх читає: трасує читання (зсув, розмір, точка коду), знаходить поля й їхні ролі та перевіряє правила довжин на файлах, яких не бачила під час навчання.

## Структура

- `rebin.py` - консольний інструмент системи.
- `experiments/` - скрипти експериментів E1-E19 та допоміжні модулі (`trace_lib.py`, `e17_inference.py`, `e18_context.py`).
- `results/` - результати запусків (текст і JSON).
- `data/corpus/` - корпус зразків за форматами (png, gif, ico, wav, gz, docx).
- `kaitai_dbg/` - згенеровані Kaitai-парсери з режимом налагодження (еталон для порівняння).

## Конвеєр

1. Трасування читання: читач відкриває файл через `CtxIO`, який записує кожне читання (зсув, розмір, функція і рядок коду) - `experiments/e18_context.py`.
2. Відновлення полів і ролей (сигнатура, константа, довжина, лічильник, CRC-32, блок даних) з урахуванням кількох файлів - `experiments/e17_inference.py`.
3. Перевірка правил довжин: правила виводяться на першій половині файлів і перевіряються на другій, з контролем зі зсувом на 1 байт - `experiments/e19_rules.py`.
4. Єдиний вхід - `rebin.py`.

## Встановлення

Середовище conda `diploma2`; потрібні пакети: Pillow, numpy, kaitaistruct.

## Використання

Вбудовані читачі (png, gif, ico, wav, gz, docx):

    python rebin.py data\corpus\png --format png --out results\rebin_png.json

Власний читач (функція, що приймає файловий об'єкт):

    python rebin.py samples\ --reader mymod:parse_file --out results\my_format.json

Експерименти E17-E19:

    python experiments\e17_inference.py
    python experiments\e18_context.py
    python experiments\e19_rules.py png gif ico wav docx

## Основні результати

- E19, правила довжин на відкладених файлах (LOOK=40, MIN_LEN=1): PNG 100 % (41 випадок), ICO 100 % (27 і 23), DOCX 100 % (157); контроль 0 %; хибні кандидати у WAV відхилено перевіркою.
- E18: від 4 до 23 точок читання на формат; назви функцій читача дають семантику полів; вкладені формати (PNG і BMP у ICO) виявляються за зміною модуля читача.
- E17: синтетичний формат XDT1 - точність меж 99,6 %, ролей 98,7 % серед збіжних полів.

## Обмеження

- Метод бачить лише ті читання, що виконуються на рівні Python; нативні декодери (наприклад, LZW у GIF) потребують інструментації виконуваного коду.
- Ширина й порядок байтів поля неоднозначні, якщо старші байти завжди нульові.
- Байти, які читач не торкався, у опис не потрапляють.
